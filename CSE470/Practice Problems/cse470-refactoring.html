Refactoring — one program, seven smells

A working semester-fee program that nobody would want to maintain. It compiles, it runs, and it prints eight lines that must not change. Your job is to find every code smell, name the Fowler refactoring that removes it, and apply them one at a time without ever breaking the output. The same program is given in Python and Java; both print exactly the same thing.

The program

FeeSystem bills one student for one semester. A RegularStudent has credits, a program, a waiver, an attendance range and a list of course fees. FeeMgr calculates the semester fee, FeeReport formats a summary line, and a VisitingStudent is billed by their home university instead.

That is the whole domain. Everything else wrong with the file is self-inflicted.

How to work: baby steps and a regression test

Refactoring is not rewriting. The distinguishing feature is that you can stop at any moment and still have a working program.

Why the output is fixed

Refactoring means changing the internal structure of code without changing its observable behaviour. For this program, observable behaviour is exactly one thing: the eight lines it prints. Fix that as a contract first, and every edit afterwards has an objective pass/fail test.

Without that contract you are not refactoring, you are rewriting — and a rewrite that quietly changes a fee by 5% is indistinguishable from a successful refactoring until a student complains.

Set the regression test up first

# capture the golden output, once, before you touch anything
python3 fee_system.py > golden.txt
javac -d out FeeSystem.java && java -cp out FeeSystem > golden_java.txt
diff golden.txt golden_java.txt        # must be empty

# after every single edit, from now on
python3 fee_system.py | diff golden.txt -   # must print nothing

diff catches the trailing blank line, trailing spaces and 40750.0 versus 40750.00. Your eye does not. Run it after every step, not at the end.

The loop

  1. Pick one smell.
  2. Pick the smallest change that removes part of it — one rename, one extracted method. Not the whole smell; one step of it.
  3. Make the change.
  4. Run the program and diff against the golden file.
  5. If the diff is empty, commit. If it is not, undo — do not debug forward. The last step was wrong and it is two lines long, so throwing it away costs nothing.
  6. Go to step 2.

The commit after each green run is what makes the undo cheap. A student who refactors for forty minutes and then discovers the output changed has no way back; a student who commits nine times has eight.

The order that works

The seven smells in this exercise are deliberately ordered by risk:

  • Rename first (smell 1). It is mechanical, an editor can do it, and it makes every other smell legible.
  • Then extract (smells 2 and 3). Extracting a method cannot change behaviour if you move the lines unchanged and pass everything they use.
  • Then move (smells 4 and 5). Moving a method between classes is where signatures change, so it is where mistakes start.
  • Then merge duplicates (smell 6). Riskiest, because the copies are never quite identical — see the 0.0 versus "" return values.
  • Then fix the hierarchy (smell 7). Largest blast radius, so it goes last, when everything else is already clean and tested.

What “preserving behaviour” does and does not cover

Byte-identical stdout is the contract for this exercise. It is not the whole of observable behaviour in general, and this program contains a reminder: replacing the in-place sortFees with a function that returns a new list changes what a caller would see if it relied on the mutation. No caller here does, so the output is unchanged — but the behaviour is not quite. Real refactoring needs real tests, not just a printed transcript.

        self.p = p

class FeeMgr:
    RATE = 4500.0
    LATE = 0.05

    def calc(self, s, sd, sm, sy, ed, em, ey, label, isLate, policy, discountLevel):
        # step 1: make sure the record is usable
        if s.getId() == "":
            print("bad id")
            return 0.0
        if s.getCredits() <= 0:
            print("bad credits")
            return 0.0
        if s.getProgram() == "":
            print("bad program")
            return 0.0

        total = 0.0
        base = s.getCredits() * FeeMgr.RATE

        if (s.getProgram() == "CSE" and s.getCredits() > 9
                and s.getWaiver() != "NONE"
                and not (em - sm > 4)
                and (s.getCredits() < 15 or s.getWaiver() == "MERIT")
                and s.getAtt().getLow() >= 60
                and not isLate):
            total = base * 0.8
        else:
            total = base

        # add up the individual course fees
        i = 0
        while i < len(s.getFees()):
            total = total + s.getFees()[i]
            i = i + 1

        low = s.getAtt().getLow()
        high = s.getAtt().getHigh()
        ok = policy.withinRange(low, high)
        if ok == False:
            total = total + 1000.0

        if discountLevel == 2:
            total = total - (base * 0.1)
        else:
            total = total - (base * 0.05)

        if isLate:
            total = total + total * FeeMgr.LATE

        print(label + " " + str(sd) + "/" + str(sm) + "/" + str(sy)
              + " - " + str(ed) + "/" + str(em) + "/" + str(ey))
        return total

    def proc(self, s):
        # step 1: make sure the record is usable
        if s.getId() == "":
            print("bad id")
            return 0.0
        if s.getCredits() <= 0:
            print("bad credits")
            return 0.0
        if s.getProgram() == "":
            print("bad program")
            return 0.0

        tmp = 0.0
        for x in s.getFees():
            tmp = tmp + x
        return tmp

    def sortFees(self, arr):
        n = len(arr)
        for a in range(n):
            for b in range(0, n - a - 1):
                if arr[b] > arr[b + 1]:
                    t = arr[b]
                    arr[b] = arr[b + 1]
                    arr[b + 1] = t
        return arr


class FeeReport:
    RATE = 4500.0
    LATE = 0.05

    def build(self, s):
        # step 1: make sure the record is usable
        if s.getId() == "":
            print("bad id")
            return ""
        if s.getCredits() <= 0:
            print("bad credits")
            return ""
        if s.getProgram() == "":
            print("bad program")
            return ""

        tmp = 0.0
        for x in s.getFees():
            tmp = tmp + x

        line = s.getName() + " | " + s.getProgram() + " | "
        line = line + str(s.getCredits()) + " cr | "
        line = line + str(s.getCredits() * FeeReport.RATE + tmp)
        return line

    def sortFees(self, arr):
        n = len(arr)
        for a in range(n):
            m = a
            for b in range(a + 1, n):
                if arr[b] < arr[m]:
                    m = b
            t = arr[a]
            arr[a] = arr[m]
            arr[m] = t
        return arr

class FeeMgr {

    public static final double LATE = 0.05;

    public double calc(RegularStudent s, int sd, int sm, int sy, int ed, int em,
                       int ey, String label, boolean isLate, AttPolicy policy,
                       int discountLevel) {
        // step 1: make sure the record is usable
        if (s.getId().equals("")) {
            System.out.println("bad id");
            return 0.0;
        }
        if (s.getCredits() <= 0) {
            System.out.println("bad credits");
            return 0.0;
        }
        if (s.getProgram().equals("")) {
            System.out.println("bad program");
            return 0.0;
        }

        double total = 0.0;
        double base = s.getCredits() * FeeMgr.RATE;

        if (s.getProgram().equals("CSE") && s.getCredits() > 9
                && !s.getWaiver().equals("NONE")
                && !(em - sm > 4)
                && (s.getCredits() < 15 || s.getWaiver().equals("MERIT"))
                && s.getAtt().getLow() >= 60
                && !isLate) {
            total = base * 0.8;

            total = base;

        // add up the individual course fees
        int i = 0;
        while (i < s.getFees().size()) {
            total = total + s.getFees().get(i);
            i = i + 1;

        int low = s.getAtt().getLow();
        int high = s.getAtt().getHigh();
        boolean ok = policy.withinRange(low, high);
        if (ok == false) {
            total = total + 1000.0;
        }

        if (discountLevel == 2) {
            total = total - (base * 0.1);
        } else {
            total = total - (base * 0.05);
        }

        if (isLate) {
            total = total + total * FeeMgr.LATE;
        }

        System.out.println(label + " " + sd + "/" + sm + "/" + sy
                + " - " + ed + "/" + em + "/" + ey);
        return total;
    }

    public double proc(RegularStudent s) {
        // step 1: make sure the record is usable
        if (s.getId().equals("")) {
            System.out.println("bad id");
            return 0.0;
        }
        if (s.getCredits() <= 0) {
            System.out.println("bad credits");
            return 0.0;
        }
        if (s.getProgram().equals("")) {
            System.out.println("bad program");
            return 0.0;
        }

        double tmp = 0.0;
        for (double x : s.getFees()) {
            tmp = tmp + x;
        }
        return tmp;
    }

    public double[] sortFees(double[] arr) {
        int n = arr.length;
        for (int a = 0; a < n; a++) {
            for (int b = 0; b < n - a - 1; b++) {
                if (arr[b] > arr[b + 1]) {
                    double t = arr[b];
                    arr[b] = arr[b + 1];
                    arr[b + 1] = t;
                }
            }
        }
        return arr;
    }
}

class FeeReport {
    public static final double RATE = 4500.0;
    public static final double LATE = 0.05;

    public String build(RegularStudent s) {
        // step 1: make sure the record is usable
        if (s.getId().equals("")) {
            System.out.println("bad id");
            return "";
        }
        if (s.getCredits() <= 0) {
            System.out.println("bad credits");
            return "";
        }
        if (s.getProgram().equals("")) {
            System.out.println("bad program");

Smell 7 of 7OO abusers

7Refused bequest

VisitingStudent inherits three methods and refuses all three. The hierarchy is asserting something that is not true.

What the smell is

Inheritance is a promise: every subclass is a superclass, and can honour everything the superclass declares. When a subclass overrides inherited methods to return nothing, return zero, or do nothing at all, it is refusing the bequest — and the promise was false.

Member declares getScholarshipPercent(), getTranscript() and payTuition(amt). A visiting student has no scholarship, no transcript from this university, and pays no tuition here. All three overrides exist purely to cancel what was inherited, and one of them is even accompanied by a comment apologising for its own existence.

The empty payTuition is the strongest signal. A method whose body is empty is a class saying this operation does not apply to me in the only vocabulary the hierarchy allows.

    public double calculateSemesterFee(RegularStudent student, Term term,
                                       boolean isLate, AttendancePolicy policy) {

            return 0.0;

        total += student.totalCourseFees();

        if (student.qualifiesForWaiverDiscount(term, isLate)) {
            return student.baseFee() * FeeRates.WAIVER_DISCOUNT_MULTIPLIER;
        }
        return student.baseFee();

    //   its own copy of the summing loop, and its own copy of the RATE
    //   constant. All three are now shared.
    // FIXES: Feature Envy
    //   Original: this method computed s.getCredits() * RATE + tmp, doing
    //   the student's arithmetic on the student's data.
    public String build(RegularStudent student) {
        if (!student.hasValidRecord()) {
            return "";
        }

        double total = student.baseFee() + student.totalCourseFees();
        return student.getName() + " | " + student.getProgram() + " | "
                + student.getCredits() + " cr | " + total;
    }
}

Three changes the output does not show

Sorting is no longer in place. The original sortFees mutated the caller's list and returned it; sorted_fees / FeeSorting.sortedFees returns a new list and leaves the argument alone. No caller here depends on the mutation, so nothing printed changes — but a caller elsewhere would notice.

A call disappeared. v.payTuition(5000.0) invoked an empty method body, so removing it removes nothing observable. Deleting a call is only safe when you have checked that the call does nothing, which is precisely what made it a refused bequest.

An assertion was added. AttendanceRange now rejects low > high. It passes for this data, and in Java it is not even evaluated unless you run with -ea.

Where the reference solution made a judgement call

NonDegreeMemberPolicy is one way to state the non-degree rules outside the hierarchy; its two methods currently ignore the member they receive. The alternative — a Billable interface that RegularStudent implements and VisitingStudent does not — pushes the same decision into the type system and is the better answer in a larger program. Either is worth full marks with the reasoning stated.

Similarly, FeeCalculator.totalCourseFees(student) survives as a one-line pass-through so that the second line of output still comes from the calculator. If you deleted it and called student.total_course_fees() from main instead, the output is identical and the design is arguably cleaner — say so and it counts.

Marking summary

  • Naming — no abbreviations, no single letters, method names name their result.
  • Comments — no comment describes what; both why comments survive.
  • Long method — nothing over about a dozen lines; the big conditional is decomposed into named predicates.
  • Parameters — four or fewer on the fee entry point; no parameter the callee could derive itself.
  • Feature envy — arithmetic lives with the data; FeeReport only formats.
  • Duplication — one summation, one validation, one sort, one copy of each constant.
  • Refused bequest — no empty bodies, no placeholder returns, Member holds identity only.
  • Behaviour — diff against the original output is empty. A submission that fails this fails the exercise, however clean the code is.
